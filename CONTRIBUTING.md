# Contributing

Thanks for your interest in dgeo!

## Development setup

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[ui,dem,dev]"
pytest -q
```

`ffmpeg` must be on your `PATH` to import non-WAV audio in the UI. `make local-ui` starts the app.

## Workflow

- Open an issue first for anything beyond a small fix, so the approach can be discussed.
- Fork, branch, open a pull request against `main`; the CI (tests on Python 3.10 and 3.12, demo,
  Docker build) must pass before merge. Pull requests are squash-merged.
- Describe your change in `CHANGELOG.md` under `## Unreleased`. Maintainers cut one release per merged
  feature (minor bump) or fix (patch bump) with `python scripts/bump_version.py minor|patch`; merging a
  version bump into `main` publishes the GitHub Release automatically. Docs/tests/CI changes ship with
  the next release.
- Security issues: see [SECURITY.md](SECURITY.md), never in public issues.

## Guidelines

- Keep the physics explicit and tested: any change to the forward model, detection or scoring should
  come with a test (synthetic scenarios are generated by `dgeo/synth.py`).
- `pytest -q` and `dgeo demo` must keep passing; the end-to-end test expects < 150 m error.
- Every source file starts with `# SPDX-License-Identifier: AGPL-3.0-or-later`.
- By contributing, you agree that your contribution is licensed under AGPL-3.0-or-later.

## Privacy

Never commit or attach real recordings, ADS-B captures, `meta.json` files, timestamps or coordinates
that could reveal where someone lives or was. Use synthetic data (`dgeo synth`) to reproduce bugs.
If a bug needs real data, describe it qualitatively.
